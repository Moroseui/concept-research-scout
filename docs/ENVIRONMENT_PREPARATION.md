# Native environment preparation

The scientific execution plan needs an authentic Python/package environment identity. Existing download receipts establish input bytes and image identity, but do not establish the packages visible to the native Python interpreter.

The `modal_environment_inventory` service performs one fixed, read-only CPU inventory of the already selected image. It has no model, GPU, patient data, Volume mounts, network access inside the container, credentials, secrets or open ports. The command emits bounded Python/platform/distribution and availability metadata; it does not import scientific packages or claim they work. Dependency closure and native positive execution checks remain separate requirements.

The existing asset ledger reserves the bounded cost before provider creation. A fixed operation and administrative owner cannot admit science or create a new opportunity after a source, price or image change. Its full reservation counts in both original item4 caps, including future fit admission. Actual billing, other commitments, HALT and unresolved-attempt checks remain applicable.

The versioned promoter must install independently reviewed source first. `tools/environment_inventory_service.py` then creates only new private configuration/state and a disabled service, verifying the installed hash list and runtime/SDK pins before writes. The service checks its actual source, unit and confinement properties before using the provider. Repeated starts observe the same recorded handle. Lost creation or incomplete output stays blocked; saved terminal output is rehashed without a second provider call.

Tests use genuine controller, worker, record and ledger code with an explicitly synthetic paid SDK endpoint. Only a later reviewed live invocation can establish the selected remote image's environment.
