# Draft item4/6 scientific stage connection

This working branch connects the actual Driver input and completed-author consumers to protected experiment scopes. It is not installed and does not yet provide the complete executor driver. Legacy saved-evidence and Sprint10 routes retain their original behavior.

The preparation plan binds a separate scientific execution-plan file. All four roles receive that exact file and hash through manual_context.prepare. Item4 uses the existing reviewed-base safe-view patcher and synthetic notebook checks. Item6 requires an author-owned analysis.program.json containing analysis.py and unittest tests; the controller scans, compiles, preserves and tests those files without supplying diagnostic code. The independent reviewer receives the actual source, tests, provenance and synthetic receipt. Approval requires a passing, hash-checked preserved synthetic receipt. Historical external evidence remains distinguished from newly returned results. Interpretation requires the execution receipt, execution manifest, package manifest, per-file validation, result tables and reviewed specification.

The existing CPU namespace/mount wrapper runs synthetic tests without network, credentials or patient mounts. Author-written tests establish only their tested behavior; the independent reviewer must assess adequacy. A passing synthetic test is not real-data execution or scientific acceptance. Original programs/notebooks and previous rounds are preserved.

Still required before any item4/6 launch: reviewed initialization and owner/parallel selection; bounded revision-policy connection; the real COMMIT_SPEC -> package -> admitted executor -> collection/validation transitions; item4 preprocessing/benchmark/fit waves and item6 CPU adapter; real composed inputs, full suites, automated review and held promotion. Until the new executor connection exists, Driver explicitly refuses to fall through to its historical Sprint10 executor. Do not initialize or reserve a scientific call from this draft.

Deterministic connected tests use labelled synthetic model artifacts and an explicitly mocked native environment boundary; the real unittest harness runs in separate Python processes on trivial synthetic source. The four native notebook-sandbox tests require the existing server CPU environment and are skipped locally when that environment is absent. No local skip is claimed as native isolation evidence. Full server gates remain required on the final integrated candidate.

The protected item4/6 preparation now binds the existing revision policy explicitly. Actual model-input construction delivers the correct 20/30-call and three-revision instructions; actual local/global reservations keep every prior call and refuse a fifth same-role call or an uncertain predecessor. Bare legacy backend/item labels do not enable the extension. This does not initialize a run, submit compute or replace the missing execution/collection transition.
