# Scientific provider output contract

Typed scientific decision stages use the existing clients' schema options: Codex `--output-schema` and Claude `--json-schema`. The schema comes from the validated packet and stage. Author judgment and opposing review have object-valued provider artifacts with their existing required fields and types. Campaign artifact envelopes retain their original string-valued file bodies. Existing native scientific validation, bindings and disposition still decide whether outputs qualify.

The runner preserves the original protocol, a canonical copy of the provider's structured field, the selected schema, command and a receipt identifying the deterministic projection into existing string-valued artifact files. The projection performs serialization only. It is not a model judgment, a new reviewer, a source identity change or approval. The raw protocol and its digest remain authoritative evidence of what the provider emitted. Historical outputs still pass the unchanged strict artifact reader; this feature provides no format-recovery exception for attempts237 or247.

Missing or malformed structured output refuses without falling back to prose. Nonempty Claude final commentary must decode to the same structured value; otherwise it remains in the original protocol and qualification refuses for reconciliation. This avoids discarding conflicting criticism. No automatic retry, refund, limit reset or scientific permission follows a refusal.

The CLI's exact `StructuredOutput` data emission may be recognized only for an active schema and a paired successful output equal to the returned structured field. It grants no filesystem or execution tool. Original events stay intact; a derived matching view excludes only that verified data emission from the separate scientific evidence-retrieval ledger. Evidence-call budgets and actual retrieval matching remain unchanged. Unlisted tools and unmatched emissions refuse. The profile still has3 model iterations without authenticated retrieval and32 only with that existing runtime; timeouts and spending controls are unchanged.

Input checks count schema characters and UTF-8 bytes separately, adding them conservatively to existing input ceilings and the original019 growth allowance. Tokens remain unmeasured. Stored-context and packet limits remain independent. Before scientific use, verify actual pinned client schema behavior, including the internal emission and final-commentary format, as both scientific service accounts; fixture tests and client `--help` do not prove that acceptance. Recompose after genuine review and provisioning.

This implementation requires independent source/integration approval and the existing deployment, audit and runtime gates before use. It does not recover247, authorize another eligibility pair or enable standing research timers. Recorded operator authority, no-retry outcomes, scientific validation and H2 acceptance/adoption gates remain separate.
