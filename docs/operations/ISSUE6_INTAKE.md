Post ordinary plain text to propose work. It is saved through the same change-request store used by agents and reports, with original comment/version attribution and pending review. Use one unquoted command as the entire comment for deterministic controls:

- `/research status` reads saved coordinator state and its control revision.
- `/research pause revision N` stops new admission/scheduling at the revision shown by status; active jobs are preserved.
- `/research resume revision N` requests resumption at the revision shown by status. It does not activate an unactivated scheduler, reset quota or stop a job.

First read status and replace N with its observed revision. Bare pause/resume commands are refused because a previously unseen old command must not acquire today's authority. Controls posted at or before the immutable intake enrollment time are preserved as historical and refused; post a fresh command after reading status. Edited controls are refused: post a new comment. A stale revision is refused rather than silently overriding a later stop. The reply distinguishes recorded receipt, pending investigator assessment and actual recorded control effects. The original historical ACK comment is recorded as information acknowledgment using its original notification binding; the expired legacy acknowledgment API is never replayed.

## Root-held proposal attestations

The fixed controller child no longer trusts parent PID or parent UID as proof of a GitHub operator. A controller-owned process can become an orphan of root-owned PID1; that is not operator authentication. Actual Claude source review identified this earlier flaw. It affected proposal attribution, not execution or reserved authority, and the original implementation/review remain preserved.

The root poller writes one immutable fetched-comment attestation under /etc/research-system/live-research/controls/issue-intake-attestations/<comment-version>.json before invoking the fixed UID997 child. The reviewed installer must create/check this fixed directory as root:controller_gid0750; files are root:controller_gid0640, explicitly set even under umask077. Existing service write access to the protected controls parent already covers this child directory. Keep the main private intake state directory0700; do not broaden it. No new socket, credential or model path is introduced.

Only the version and attestation SHA travel on stdin. The child reads the fixed file, verifies all ancestor ownership/access, regular-file ownership/mode, exact bytes, source, comment version and original/received payload digest, then uses the existing change-request submission and deduplication. It never accepts caller-supplied original prose as a human attestation. Replaying a genuine record can only reproduce the same attributed saved proposal; changed code/source or comment bytes cannot silently reuse it. Edits remain distinct received versions. Attestations and originals remain preserved after receipt, response loss or restart.

Directory absence or wrong ownership produces a named refusal; it does not fall back to PPID inference. Read-only diagnosis can inspect metadata without executing a control. Production parent/child acceptance is still required after exact source/configuration review; unit tests use explicitly synthetic file-ownership fixtures.
