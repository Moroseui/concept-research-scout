# Runtime prerequisite delivery before scientific admission

A successful operational check is not evidence delivered to a scientific role.
The primary source-bound change application may now declare `runtime_prerequisites`:
at most eight exact completion-event/original-artifact bindings (12,000 UTF-8 bytes
in total). The existing authenticated change store preserves the original proof;
the current-state application keeps its status, source and reference visible.
No proof body or entire historical archive needs repeating in every prompt.

The normal scientific capture constructor validates the selected application and
completion records, source/authorization/technical-event identities and exact proof
bytes inside the same native prefix used by the author and independent reviewer.
Controller input preflight runs this check before admission. The protected broker
runs it again when constructing the role capture. Missing, changed, stale-prefix
or out-of-scope evidence refuses; an external file or a launch-script check cannot
substitute. Existing role readers deliver the authenticated originals. This does
not create a new retrieval service, authority grant or scientific judgment.

The single eligibility263 reconsideration additionally requires its exact human
seven-condition authorization and reviewed source applications. Its preserved
DEFER, opposing approval and sealed decision must remain readable in the capture.
The old263 decision is verified through the original-only native reader; it is
never converted to approval. The protected authorization event owns one reservation
across source, template and day changes. Failure, uncertainty or another DEFER
cannot fall through to a fresh bootstrap. All ordinary scientific gates remain.

Prerequisite completion uses a DISPOSITION observation, not a replacement APPLIED
implementation binding. An independent review must approve the primary application
that selects it. The original technical proof retains its actual source identity;
reuse on a successor requires applicable source/integration and deployed checks.
The proof alone does not establish that the successor is installed or functional.

Checks: `tests/test_scientific_runtime_prerequisites.py` and
`tests/test_investigator_eligibility263_reconsideration.py`, plus existing authority,
protected reservation and scientific evidence runtime tests. Synthetic checks do
not prove service-account access or live-client behavior. Before use, qualify the
independent review, recompose genuine history, verify consuming role readers,
complete applicable release/audit gates and record actual execution separately.

The new reconsideration keeps four current-state namespaces. Its replaced247 grant
remains independently discoverable through the exact original263 packet and that
packet's authenticated old change prefix. This uses the existing bounded capture
and original-only broker reader; it neither broadens current authority nor raises
record, namespace-selection, prompt or retrieval limits. Historical packet bytes
are stored once in the capture, not repeated in the current prompt.
