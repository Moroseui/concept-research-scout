The correction compares billing freshness with the clock after the response; explicit deterministic test clocks stay fixed and future/stale billing still refuses.

A successor configuration can include `prepared_from` with the original root-preserved config path and SHA256 and the original binding SHA256. The original package, provider settings, ledger, state, owner, expiry and reserved envelope remain exact. Original configuration, units, source and all evidence remain unchanged. Only new versioned config/unit/executable files are provisioned, disabled.

The old configuration cannot itself be a continuation. No scientific allowance or retry after a provider intent is granted.

Each live tick rechecks the root-bound predecessor and held units, then verifies the original binding byte hash and canonical hash. The original owner is re-used, not re-registered with the successor source.
