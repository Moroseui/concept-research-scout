# Experiment initialization and accounting connection

The new experiment_driver command initializes one protected item4 or item6 lane.
It verifies the exact implementation review, runtime file and preparation-plan
hash; the actual backlog selection, prerequisite acceptance rows/report hashes,
all registered evidence views, compact context and synthetic environment; and
release/authority source files before creating a state or owner. It then uses
the existing ManualExecutor scientific-call ledger and CAS policy, with the
existing twenty/thirty-call amendments. Native calls still use manual_stage and
manual_context. No alternate model client or input assembler is introduced.

The model author writes scientific code; this module supplies stage instructions
and bindings only. It must not use CPUExecutor's Sprint10 reproduction or the
analysis-only saved-evidence transition for these experiments.

A stable canonical owner prevents a release/plan/group change from creating a
second allowance. Only the specifically authorized item4 and item6 owners may
coexist; the other owner's protected plan and lane binding must match. Ordinary
registration remains exclusive. Scientific RUNNING/UNCERTAIN checks and shared
UTC-day/batch caps remain unchanged. No existing row or allowance is reset.
A partial initialization remains visible and refuses another init.

Tests construct exact current source with labelled synthetic evidence/native
verifiers. They run the actual initializer, Driver guard/input preparation,
notebook validator, local CAS/global SQLite reservation, prerequisite receipt
consumption, duplicate refusal and parallel-owner gates. They make no model,
provider or patient-computation call. They are not live deployment evidence.

Still required before live use: the actual execution-plan and protected intake
selection; executable provider packaging, execution/observation/collection and
validation connections; final reviewed STATE/report transitions; promoter/service
entrypoint selection; both full server suites, independent implementation review,
held installation and live checks. EXECUTE_EXPERIMENT remains an explicit refusal
until that connection is implemented. This is not M4 completion.
