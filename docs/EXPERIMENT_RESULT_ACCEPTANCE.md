# Experiment result acceptance connection

An approved experiment run reaches interpretation only after original aggregate returns pass the reviewed execution contract and existing local/global collection accounting. Acceptance verifies those originals again, checks their exact delivery to both scientific roles, and requires the independent reviewer's accepted server-side submission: APPROVE with no findings. Prose does not supply a verdict.

The author supplies the interpretation and next decision. The controller preserves those bytes, their review, validation and bindings, commits a compact STATE reference, writes the run report, and completes the existing owner. A completed run does not complete unexecuted stages of a backlog item or authorize its proposed successor.

The shared context predicates keep validation files in the same delivery channel used by the assembler. Historical next-decision blocker bindings are checked against the author's authenticated original input, so a later cited closure neither rewrites the proposal nor reopens the finding. Current obligations remain subject to the normal preflight.

Finalization saves a hash-bound file intent before repository writes. Unexpected edits refuse; recovery after a Git commit reuses the same bytes. Repeated completion verifies the same results, report and event, without another provider operation, model call, allowance or charge. A completed global owner only permits report/final-state reconciliation when its accepted report hash matches.

## Deterministic evidence and limits

`tests/test_experiment_acceptance.py` connects real aggregate validation, collection ledgers, workspace composition, submit_review verification, Git commit and final accounting. It includes changed/missing evidence, non-approval verdicts, closure provenance, unrelated edits, interrupted finalization and repeat completion. Scientific results, model events, provider responses and root provenance are explicitly synthetic. `tests/test_experiment_driver.py` covers real initialization/accounting and completed-owner refusal outside finalization.

This is an uninstalled engineering candidate. It supports result acceptance for the item 4 Modal path; item 6 execution, concrete preprocessing/provisioning, monitored checkpoint continuation, live scientific execution and integrated deployment/review remain separate requirements. No synthetic test is evidence that a research experiment ran or that M4 is complete.
