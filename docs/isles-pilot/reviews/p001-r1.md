## Review verdict: REVISE — three blocking findings, none of which undermine the overall design

The core scientific machinery is sound: admission-only input timing is enforced by construction (predictions are computed and persisted before the label file is ever opened, `run.py:run`), the frozen 99-case boundary is enforced by the SHA-pinned cohort table plus anchored per-case path regexes so reserved IDs cannot enter selection, no outcome-derived column is read (only `case_id`, sorted, all else discarded), and the metrics/bootstrap implementation matches SPEC exactly (Dice edge cases, seed 20260905, 2,000 resamples, lexical row order frozen consistently in both `run.py` and `validate_return.py`). The hash-binding chain (`verify_decision` → binding.json → checkpoint bindings) fails closed on any spec/code drift, which is what makes approval of exact bytes meaningful. But three things must change before this revision is acceptable to bind.

### Blocking findings

**B1 (HIGH) — `predict()` diverges from SPEC's prediction predicate; likely real-data abort.** `campaigns/isles24-pilot/experiments/P001/run.py:predict` raises on *any* non-finite voxel. SPEC.md says "Predict finite Tmax > 6.0 seconds" — the natural reading is the predicate `finite ∧ >6`, treating non-finite voxels as non-lesion; if abort-on-any-nonfinite were intended, "finite" in the predicate is redundant. Perfusion-map derivatives commonly carry NaN backgrounds, so as written the first case can kill the entire receipted run and force amendment churn mid-campaign. Fix (pick one, pre-run, so spec and code agree at binding time): change to `np.isfinite(tmax) & (tmax > 6.0)` and record a per-case non-finite voxel count in the checkpoint for transparency, with a unit test asserting a NaN-background map predicts False at NaN voxels without raising; or amend SPEC to state explicitly that any non-finite voxel is an input-integrity stop.

**B2 (HIGH) — the committed notebook cannot pass its own authority gate at its pin.** `colab_P001.ipynb` pins `45c4a5d`, a commit that structurally cannot contain `review.json` (the runner refuses to execute without it, so it can only be committed later). Cell 03 therefore always raises at that pin. The only working path is dropping an untracked `review.json` into the checkout — which slips past the clean-tree assert because it uses `--untracked-files=no` — directly contradicting the notebook's own "review must be committed" text, and it's documented nowhere. The hash checks in `verify_decision` do fail closed if the pinned `SPEC.md`/`run.py` bytes differ from the reviewed ones, so no unreviewed code can run; but the deliverable as supplied is a notebook that can never complete Run All legitimately. Fix: after the review receipt lands, regenerate both notebooks via `scripts/package_pilot.py --pin <commit containing review.json>`, commit them, and document that re-pin step in SPEC.md or CAMPAIGN.md as a required post-review action.

**B3 (MEDIUM) — broad clone fetches raw patient-derived blobs onto the Colab VM (operator-flagged; confirmed).** The setup cell in both notebooks and `scripts/package_pilot.py` does a full `git clone`, which fetches all advertised refs. Per PROGRESS.md's own audit, the 047 results branch — and only that branch — reaches the 173 distinct raw phenotype blobs, and remote cleanup has not executed. So the pilot clone materializes unrelated raw patient-derived data into a third-party runtime for no reason, against the campaign's data-minimization posture. Bounded fix, supported by the supplied reachability evidence: `git clone --single-branch --branch astra/autonomous-isles-pilot --filter=blob:none` (the pin is on that branch), or `git init` + shallow fetch of the exact pin.

### Non-blocking findings

- **Missing campaign route in `scout.py` (operator-flagged; confirmed, MEDIUM).** `main()` wires no campaign subcommand: P001 preflight, `validate_return.py`, `package_pilot.py`, and the publication audit all run as loose scripts outside the receipted/scope-guarded orchestration the repo otherwise mandates. Fix: add a `campaign` subcommand group delegating to the existing modules. Relatedly, `orchestrator/publication.py:check_git_paths` is not visibly invoked anywhere in the supplied material — its wiring presumably lives in the unsupplied `scripts/check_pilot_publication.py`, which I could not verify.
- **Checkpoint/index atomicity (LOW), `run.py:run`.** A crash between `save(checkpoint)` and the index update makes resume refuse with the misleading "checkpoint metric bytes changed", permanently poisoning the output path. Fix: build checkpoint bytes in memory, hash, write the index entry first, then the checkpoint (a stale index entry with no checkpoint is harmless — the case just recomputes).
- **Failure card poisons pre-binding retries (LOW), `run.py:__main__`.** A failure before binding.json exists writes `RESULT_CARD.md` into `out`; the retry then hits "nonempty destination lacks campaign checkpoint binding" on the notebook's fixed Drive path. Write the failure card under `.private/failed_attempts/` instead.
- **`reserved_cases_selected: 0` in preflight is asserted, not computed** — true by construction only; rename or derive it.
- **`validate_return.py` uses exact float equality** — reproduction requires the pinned numpy 2.3.3; document that the validator must run under `requirements.txt`.
- **`_mount_cell` catches only `SecretNotFoundError`**; a defined-but-ungranted `HF_TOKEN` raises `NotebookAccessError` and crashes the mount cell.
- **`execution_receipt.json` hardcodes `gpu_minutes: 0`** rather than checking the runtime.
- **`CHECKPOINT.json` is stale as supplied**: tip `68298a8` ≠ reviewed revision `495269bc`, which appears nowhere in its commit list.
- Cosmetic: dead `if policy_path.exists():` immediately after the mandatory refusal in `scout.py:record_result`; 7z prints member paths (case IDs) into the private console — acceptable per SPEC, but `-bb0` would keep the console lean.
