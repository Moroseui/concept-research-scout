**How the probe implements the contract:**
- **One command, no knobs.** `python3 run.py` is the real probe; `--smoke` is the only flag. The three executions (A, B, A-repeat), batch size 1, seed 0, and the 45-GPU-minute cap are hardcoded; at startup the contract's caps are re-read and the run aborts if they differ from the frozen constants, so a silent contract edit can't loosen the probe.
- **Deterministic manifest.** The pair is not hardcoded (no frozen Stage-0 pair list exists in the repo): it is re-derived from the released `validation_metadata.csv` by exact string equality on RescaleSlope, RescaleIntercept, XYSpacing, ZSpacing, NumberofSlices plus position/acquisition columns where present, restricted to Br40f|Br60f, sorted, first taken — selected before any score is seen. The qualifying-pair count is logged against Stage 0's 237 as a drift cross-check.
- **Split guards.** Every download and both pair members pass through a guard refusing anything train- or test-split; the pair is asserted to be two distinct reconstructions of one acquisition. Labels are never used in any endpoint (read only because the released dataset class requires the file, and for the head-name/order check against the released 18-column order).
- **Provenance before inference**, strict `load_state_dict`, bit-identity via raw byte comparison of the score vectors, and exit codes 3–9 mapped one-to-one to the contract's seven invalidating failures (11 = missing dependency, 12 = internal error, never a negative result).
- **Released-code fidelity.** Model construction and the 18 head names were transcribed from the official `ct_lipro_inference.py` / `data_inference_nii.py`, fetched from the CT-CLIP repo today. Since I could only transcribe, not execute, `verification.json` flags this as PASS_WITH_CAVEAT: a signature mismatch fails loudly with exit 5/7/9, and the rule stated in the README is fix-the-driver, never the released code.
